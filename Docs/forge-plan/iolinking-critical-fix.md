# Critical Fix: IoLinking FC generates wrong variable names and wrong instance DB names

Two bugs in `src/lib/forge-prompts.ts` inside `buildIoLinkingPrompt()` cause ALL IoLinking compile errors (25 errors in current build). Both must be fixed together.

---

## Bug 1: FB interface extraction regex never matches

The IoLinking prompt extracts FB parameter names from the generated device FB artifacts so the AI knows what variable names to use. The extraction regex looks for `INTERFACE...END_INTERFACE` — but that doesn't exist in SCL. SCL uses `VAR_INPUT...END_VAR`, `VAR_OUTPUT...END_VAR`, etc.

Because the regex never matches, the AI receives ZERO actual parameter names and invents its own. This causes every single `"Tag not defined"` compile error:
- AI writes `"InstPE01".sensorInput` → actual parameter is `"InstPE01"._Sensor`
- AI writes `"InstM01".feedbackRun` → actual parameter is `"InstM01".runFeedback`
- AI writes `"InstM01".runCmdFwd` → actual parameter is `"InstM01".fwdRun`
- AI writes `"InstCV01".pe01Detected` → actual parameter is `"InstCV01".endSensorForward`

### Fix:

In `src/lib/forge-prompts.ts`, inside `buildIoLinkingPrompt()`, find the interface extraction block (around line 442):

```typescript
// CURRENT — BROKEN
const match = a.content.match(/INTERFACE\s*([\s\S]*?)END_INTERFACE/i);
return match ? `### ${a.name}\n\`\`\`\nINTERFACE\n${match[1].trim()}\nEND_INTERFACE\n\`\`\`` : null;
```

Replace with:

```typescript
// FIXED — matches actual SCL VAR sections
const interfaceRe = /(VAR_INPUT[\s\S]*?END_VAR|VAR_OUTPUT[\s\S]*?END_VAR|VAR_IN_OUT[\s\S]*?END_VAR)/gi;
const matches = a.content.match(interfaceRe);
return matches ? `### ${a.name}\n\`\`\`\n${matches.join("\n")}\n\`\`\`` : null;
```

This is the same regex already used correctly in `src/hooks/use-forge-process-generate.ts` at line 40.

## Bug 2: AI doesn't know the actual instance DB names

Instance DBs are generated by stripping non-alphanumeric characters:
```typescript
const instDbName = `Inst${device.name.replace(/[^A-Za-z0-9]/g, "")}`;
```

So device name `PB_START` produces instance DB `InstPBSTART` (underscore stripped).

But the IoLinking prompt only passes the raw device name to the AI. The AI sees `PB_START` and constructs `"InstPB_START"` — which doesn't exist. TIA reports `Tag "InstPB_START".buttonInput not defined` when the real DB is `"InstPBSTART"`.

This affects every device with underscores or special characters in its name: `PB_START`, `PB_STOP`, `PE01`, `PE02`, etc.

### Fix:

In `src/lib/forge-prompts.ts`, inside `buildIoLinkingPrompt()`, change the device list formatting:

FROM:
```typescript
const deviceNames = devices.map((d) => `  - ${d.name} (tag: ${d.tag})`).join("\n");
```

TO:
```typescript
const deviceNames = devices.map((d) => {
  const instDbName = `Inst${d.name.replace(/[^A-Za-z0-9]/g, "")}`;
  return `  - ${d.name} (tag: ${d.tag}, instanceDB: "${instDbName}")`;
}).join("\n");
```

And add this instruction to the prompt text, near the existing HARD RULE about variable names:

```
⛔ INSTANCE DB NAMES: Use the EXACT instanceDB name from the device list above. Do NOT construct instance DB names yourself — they may differ from the device name due to character stripping. For example, device "PB_START" has instanceDB "InstPBSTART" (no underscore), NOT "InstPB_START".
```

### Also fix the same issue in:

1. `buildProcessSclPrompt()` / `buildProcessSclUserMessage()` — if device names are passed to the process code AI, include the actual instance DB names using the same formula.

2. `buildProcessFcPrompt()` (if it exists) — same fix.

Search the entire `forge-prompts.ts` file for any place device names are formatted for AI consumption and add the instanceDB name alongside each one.
