# Pac-Forge — Runnable Code + HMI Roadmap

**Purpose:** the single, maintained backlog for exactly one goal — get **the app**
to the point where it can *generate* PLC code that *compiles, downloads and runs*,
plus the operator HMI, at the fidelity of a hand-commissioned project, **for any
new/unseen project with little-to-no hand-authoring**. This board tracks the app's
*capability*, not the completion of any one project. Done = the pipeline reaches
this quality on a *different* project (see G9). Nothing else belongs on this board.

**Reference / quality bar (NOT the target):** `exports/SRL-1427-500802-PACKML/` — the
HRE Segment Wagon project, generated by the SP-4 Code Builder then hand-finished
during commissioning. The delta between what the app emitted and what shipped *is*
the capability gap this roadmap closes; the export serves as the quality bar and a
regression fixture, never as the thing to reproduce. See `Docs/COMMISSIONING-NOTES.md`
and the export `README.md`.

## The root insight

The app already generates the layers the FDS *models* (EM state machines, UDTs,
instance/command DBs, MAP skeletons, thin UC stubs, EM+MAP OB1 calls) — and those
match the export closely. Everything that was hand-authored during commissioning is
**controls-engineering data the FDS does not capture today**: drive telegrams,
sensor fail-safe polarity, coordination policy, envelope geometry, maintenance
overrides, and the HMI. So the critical-path prerequisite for most groups is
**G0 — extend the spec contract**. The deterministic writers can only emit what the
contract models.
